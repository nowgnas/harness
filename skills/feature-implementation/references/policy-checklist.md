# 정책 점검 체크리스트 (백엔드)

기능마다 해당하는 항목만 판정한다. 각 항목의 질문은 예시다. 요구사항에 맞게 구체화해서 묻는다.

| # | 영역 | 확인할 것 | 질문 예시 |
|---|---|---|---|
| 1 | 행위자·권한 | 누가 할 수 있나, 타인의 리소스 접근, 권한 없을 때 응답 | "관리자도 타인 주문을 취소할 수 있나요? 권한이 없으면 403인가요, 404인가요?" |
| 2 | 입력·검증 | 필수값, 형식, 길이·범위, 중복 허용, 정규화(공백, 대소문자) | "수량의 최소·최대값은? 같은 상품을 중복 추가하면 합치나요?" |
| 3 | 비즈니스 규칙 | 계산식, 조건 분기, 규칙 간 우선순위, 한도 | "쿠폰과 포인트를 동시에 쓰면 어느 쪽을 먼저 적용하나요?" |
| 4 | 상태 전이 | 허용되는 상태와 전이, 이미 처리된 건에 다시 요청할 때 | "배송 중인 주문도 취소할 수 있나요? 이미 취소된 건이면 에러인가요, 성공인가요?" |
| 5 | 경계·예외 상황 | 0건, 최대치, 부분 실패, 대상 없음 | "대상이 0건이면 빈 목록인가요, 에러인가요?" |
| 6 | 동시성·멱등성 | 중복 요청(재시도, 더블클릭), 동시 수정 충돌 | "같은 요청이 두 번 오면 한 번만 처리해야 하나요? 멱등키가 있나요?" |
| 7 | 데이터 | 기존 데이터 처리(마이그레이션·백필), 삭제 방식(soft/hard), 보존 기간, 이력·감사 | "기존 레코드의 새 컬럼은 어떤 값으로 채우나요? 삭제 이력을 남겨야 하나요?" |
| 8 | 외부 연동 | 외부 시스템 실패 시 동작(재시도, 보상, 사용자 응답), 타임아웃 | "결제사 응답이 타임아웃이면 주문을 실패로 보나요, 보류로 두나요?" |
| 9 | 이벤트·알림 | 발행 대상과 시점(커밋 전/후), 소비자 영향 | "주문 취소 이벤트를 누가 구독하나요? 스키마를 바꿔도 되나요?" |
| 10 | 응답·에러 | 에러코드·메시지 규약, 페이징·정렬 기본값 | "기존 에러코드 체계에 새 코드를 추가하나요?" |
| 11 | 비기능 | 응답 시간·처리량 기준, 대량 데이터, 로깅·모니터링, 개인정보 | "한 번에 최대 몇 건까지 처리해야 하나요? 로그에 남기면 안 되는 필드는?" |
| 12 | 호환성·배포 | 기존 클라이언트 영향, 기능 플래그, 배포 순서(DB 먼저 등), 롤백 | "구버전 앱이 이 필드 없이 호출해도 동작해야 하나요?" |
| 13 | 시간·지역·금액 | 타임존, 영업일·공휴일, 통화, 반올림 규칙 | "마감 시각은 KST 기준인가요? 금액 소수점은 버리나요, 반올림하나요?" |

## 판정 기록 형식

```
| 영역 | 판정 | 내용 | 근거 / 질문 |
|---|---|---|---|
| 상태 전이 | ✅ | PAID 상태에서만 취소 가능 | `Order.java:88` cancel() 가드 |
| 동시성 | ❓ | 중복 취소 요청 처리 | Q2 |
| 금액 | ⚠️ | 환불 금액은 원 단위 버림 | 기존 `PriceCalculator` 관례를 따름, 확인 필요 |
```

## 질문 작성 요령
- 한 질문에는 한 가지 결정만 담는다.
- 선택지와 추천안을 함께 준다: "A(추천: 기존 X와 일관됨) / B / C"
- 답이 설계를 크게 바꾸는 질문을 먼저 묻는다.
- 코드를 보면 알 수 있는 것은 묻지 말고 직접 확인한다.
