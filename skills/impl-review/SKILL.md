# Impl Review

구현한 에이전트가 자기 코드를 리뷰하면 구현할 때의 가정을 그대로 공유해 같은 실수를 놓친다.
이 스킬은 **구현 맥락이 없는 리뷰어**에게 결과물만 넘겨서 리뷰받는다.
경로는 모두 이 SKILL.md가 있는 디렉터리 기준 상대 경로다.

## 1. 리뷰 범위 확정
| 넘길 것 | 기본값 |
|---|---|
| 변경 범위 | `git diff <base>...HEAD` + 작업 트리 변경(`git diff`, 새 파일). base는 DESIGN.md의 기준 커밋, 없으면 기본 브랜치와의 merge-base |
| 기준 문서 | `.design/<slug>/DESIGN.md` 또는 `BUGFIX.md`. 없으면 사용자 요청을 성공 기준 3~5줄로 정리해서 넘긴다 |
| 레퍼런스 기능 | DESIGN.md 4절의 경로 |
| 체크리스트 | `references/review-checklist.md`의 **절대 경로** |

**넘기지 않을 것**: 구현하면서 한 고민이나 "이렇게 한 이유" 같은 설명. 리뷰어는 코드와 설계 문서만 보고 판단해야 한다.
설계 결정은 DESIGN.md의 결정 이력에 이미 있으므로 그것으로 충분하다.

## 2. 리뷰어 실행
위에서부터 쓸 수 있는 첫 번째 방법을 쓴다.

| 환경 | 방법 |
|---|---|
| Claude Code | `impl-reviewer` 서브에이전트에 위임 |
| Codex | 새 세션으로 실행: `codex exec -s read-only -C <레포 루트> "<리뷰 프롬프트>"` |
| 둘 다 불가 | 체크리스트로 직접 리뷰하고, 결과에 **"독립 리뷰 아님"**을 명시 |

리뷰 프롬프트 (값을 채워서 그대로 쓴다):
```
너는 이 레포의 독립 코드 리뷰어다. 파일을 수정하거나 생성하지 말고 읽기와 검증 명령만 실행한다.
- 리뷰 대상: `git diff <base>...HEAD` 와 작업 트리 변경(`git status`, `git diff`)
- 기준 문서: <DESIGN.md 또는 BUGFIX.md 경로> — 성공 기준, 정책 결정, 변경 범위를 기준으로 삼는다
- 레퍼런스 기능: <경로들> — 컨벤션 비교 기준
- 체크리스트: <review-checklist.md 절대 경로> 를 먼저 읽고 항목별로 확인한다
- 반환: 체크리스트 문서의 "반환 형식"을 따른다
```

## 3. 결과 처리 (구현자)
지적마다 처리 결과를 단다: **반영** / **보류**(이유) / **반박**(근거 `path:line`)

| 심각도 | 처리 |
|---|---|
| 🔴 Blocker, 🟠 Major | 반영한다. 설계나 정책을 바꿔야 반영할 수 있으면 멈추고 사용자에게 묻는다 |
| 🟡 Minor, ⚪ Nit | 작고 설계 범위 안이면 반영하고, 아니면 후속 작업으로 넘긴다 |
| ❔ 질문 | 코드로 답할 수 있으면 답을 적고, 정책 문제면 사용자에게 올린다 |

- 반영한 뒤에는 빌드와 테스트를 다시 돌린다.
- Blocker를 고쳤으면 고친 부분만 한 번 더 리뷰받는다. **리뷰는 최대 2라운드**까지만 한다.
- 결과는 `templates/REVIEW.md` 형식으로 `.design/<slug>/REVIEW.md`에 저장한다.
  - 단독으로 리뷰를 요청받아 `.design`이 없으면 `.design/<YYYYMMDD>-review/`에 저장한다. 폴더를 새로 만들 때는 `printf '*\n' > .design/.gitignore`도 함께 한다.
