# 백엔드 관점 체크리스트

각 관점에서 **답해야 할 질문**과 **찾는 방법**. 레포에 해당 없는 관점은 "해당 없음"으로 짧게 적고 넘어간다.

## 1. 정체성
- 이 서비스는 누구에게 어떤 가치를 제공하나? 비즈니스 도메인은?
- 모놀리스인가, MSA의 한 조각인가? 조각이라면 이웃 서비스는?
- 찾기: README, 패키지/네임스페이스 최상위 이름, 컨트롤러 이름, `docs/`, 배포 매니페스트의 서비스 이름

## 2. 구조
- 모듈/프로젝트 간 의존 방향 (순환은 없나)
- 레이어 구분: controller/api → service/application → domain → repository/infrastructure
- 헥사고날(`port`, `adapter`), Clean Architecture(`Domain`, `Application`, `Infrastructure`), CQRS(`command`, `query`, MediatR) 여부
- 공통 모듈(`common`, `core`, `shared`)에 무엇이 들어 있나 — 비대하면 리스크

## 3. 진입점
- HTTP / gRPC / 메시지 / 스케줄 / CLI 각각 몇 개, 어디에
- 공통 전처리: 필터, 인터셉터, 미들웨어, AOP, 예외 핸들러
- API 버저닝과 문서화(OpenAPI) 여부

## 4. 도메인 로직
- 핵심 엔티티/애그리거트와 상태 전이 (enum `Status` 필드, 상태 머신)
- 비즈니스 규칙이 어디에 있나: 엔티티 메서드 vs 서비스 vs SQL/프로시저
- 도메인 이벤트 발행 여부

## 5. 데이터
- DB 종류/개수, 스키마 소유권 (이 서비스만 쓰나, 공유 DB인가)
- ORM/매퍼, 쿼리 작성 방식, 복잡 쿼리 위치
- 트랜잭션 경계, 격리 수준, 락(비관/낙관 `@Version`, `RowVersion`)
- 마이그레이션 도구와 이력, 시드 데이터
- 읽기 전용 복제본/라우팅 데이터소스 여부

## 6. 연동
- 동기 호출: 대상 서비스, 타임아웃/재시도/서킷브레이커 설정
- 비동기: 발행·구독 토픽/큐, 메시지 스키마, 순서 보장/중복 처리(멱등성), DLQ
- 트랜잭션과 메시지 발행의 원자성 (아웃박스, `@TransactionalEventListener(AFTER_COMMIT)`)
- 캐시: 대상, 키, TTL, 무효화 시점

## 7. 보안
- 인증 방식(JWT, 세션, OAuth2/OIDC, API Key), 토큰 검증 위치
- 인가: 역할/권한 체크 위치(어노테이션, 정책, 수동 체크)
- 시크릿 주입 방식(환경변수, Vault, K8s Secret, Key Vault, user-secrets) — **값은 기록 금지**

## 8. 설정
- 환경(프로파일) 목록과 오버라이드 순서
- 기능 플래그
- 환경변수로만 주입되는 필수 키 목록 → 로컬 실행 문서에 반영

## 9. 운영
- 로컬 실행에 필요한 것 (DB, 브로커 — docker-compose 여부)
- 빌드/테스트 명령, CI 단계, 배포 대상(K8s, VM, 서버리스)
- 로그 형식(JSON?), 상관관계 ID, 메트릭, 트레이싱(OpenTelemetry), 헬스체크 엔드포인트
- 알람/대시보드 링크가 문서에 있는지

## 10. 품질과 리스크
- 테스트 분포(단위/통합/E2E), 커버되지 않은 핵심 로직
- 핫스팟 × 큰 파일 × 테스트 부재가 겹치는 곳 = 최우선 리스크
- 오래된 프레임워크/런타임 버전, EOL 여부
